# Código copiado do T3 Code

O [T3 Code](https://github.com/pingdotgg/t3code) é MIT (Copyright (c) 2026 T3 Tools Inc.). Tudo o que este repositório copia dele fica registrado aqui, com a origem, o commit e as adaptações. Cada parte guarda a atribuição: um `NOTICE` no pacote, um cabeçalho no arquivo ou o arquivo `LICENSE-T3` ao lado.

Para ver o que mudou no upstream desde o commit registrado de cada parte:

```bash
export T3CODE_DIR=~/caminho/do/t3code               # checkout local do upstream
node scripts/upstream_t3.ts status                     # partes com mudança no upstream, arquivos e commits
node scripts/upstream_t3.ts diff effect-acp            # diff do upstream de uma parte, do commit registrado até o HEAD
node scripts/upstream_t3.ts status --upstream ~/t3code --ref origin/main
```

O checkout do upstream vem de `--upstream` ou da variável de ambiente `T3CODE_DIR`; sem nenhum dos dois, o script para com uma mensagem. O script só lê o git do upstream (`rev-parse`, `rev-list`, `diff`); para comparar com o `main` remoto, rode `git fetch` lá antes e passe `--ref origin/main`.

Ao atualizar uma parte, copie de novo, refaça as adaptações listadas e troque o commit e a data na tabela.

## Inspirado no T3, sem cópia de código

Não entram na tabela, porque não há arquivo de origem a acompanhar; quem mexer neles pode conferir o original:

- `packages/mcp/scripts/construir-executavel.ts`: segue o `build:exe` do T3 (Node SEA).
- `packages/mcp/src/ferramentas/registrar.ts`: segue o `registerImageTool` do T3.
- `scripts/sincronizar_repos.ts`: segue o `sync:repos` do T3.
- `apps/server` (servidor local do app, M1.1):
  - a rota do RPC (`servidor.ts`) segue a rota `/ws` de `apps/server/src/ws.ts`: um `RpcServer` sobre `RpcServer.makeProtocolWithHttpEffectWebsocket`, a autenticação antes do upgrade e as opções `WS_RPC_SERVER_OPTIONS`;
  - a autenticação (`Autenticacao.ts`) segue o `EnvironmentAuth.ts` (`authenticateWebSocketUpgrade`, as origens confiáveis de `isBrowserOriginAllowed`, o `wsTicket` na URL), reduzida a um token do processo pai;
  - a partida (`partida.ts`) segue o `DesktopBackendBootstrap` (`packages/contracts/src/desktopBootstrap.ts`) e o `bootstrap.ts`: um envelope JSON numa linha do stdin;
  - o encerramento segue o `cli/server.ts` (`awaitLauncherLoss` em corrida com o servidor).
- `apps/desktop` (app Electron, M1.1):
  - o processo do servidor (`servidor.ts`) segue o `DesktopBackendManager.ts` e o `DesktopBackendConfiguration.ts`: o Electron como Node (`ELECTRON_RUN_AS_NODE=1`) sobre o bundle, o bootstrap numa linha do stdin (como o T3 faz no WSL) e o encerramento com prazo, SIGTERM e SIGKILL (`BACKEND_QUIT_STOP_TIMEOUT`);
  - a janela segue o `DesktopWindow.ts` (`contextIsolation`, `sandbox`, `setWindowOpenHandler`, `will-navigate`) e o preload segue o `preload.ts` (`contextBridge.exposeInMainWorld`, IPC por `invoke`);
  - o protocolo `simplifica://app` segue o `ElectronProtocol.ts`, com uma CSP mais estreita;
  - o empacotamento (`scripts/empacotar.ts`) segue o `createBuildConfig` de `scripts/build-desktop-artifact.ts` (staging sem dependências, `extraResources`, NSIS, dmg), e o bundle do servidor deixa o `undici` de fora como `scripts/lib/cli-external-packages.ts`;
  - a ponte MCP no app empacotado usa o `selfInvocationArgs` já copiado (`packages/motor/src/t3/nodeRuntime.ts`), em `apps/server/src/ponte.ts`;
  - a atualização do app (`src/atualizacaoApp.ts`, M1.10) segue o `apps/desktop/src/updates/DesktopUpdates.ts` (commit `a6d91409729be6ba854b3f16adedc08847e3b24c`), reduzida: o `electron-updater` na mesma versão (6.8.9); `motivoDesligado` é a regra do `getAutoUpdateDisabledReason` (política, feed, app empacotado, variável de ambiente, plataforma), traduzida, mais a assinatura de código; o feed `generic` por `setFeedURL`, como o T3 faz com o espelho da política gerenciada (`DesktopUpdatePolicy.ts`), e nunca o provider `github`; encerrar o servidor antes do `quitAndInstall`, como o T3 para os backends.
